Not Just Code Monkeys เป็นหนึ่งในวิทยาทานของ Martin Fowler ได้นำเสนอแนวคิดว่า Software Developer ไม่ควรเป็น Code Monkeys (การเขียนโค้ดตามคำสั่งเหมือนหุ่นยนต์) แต่ควรเป็นมืออาชีพ


Fowler ชี้ให้เห็นว่าปัญหาใหญ่ของกระบวนการ Agile ในปัจจุบันคือการที่ Dev เป็นเพียง Requirement มาทำต่ออย่างเดียว ซึ่งขัดกับหัวใจสำคัญของ Agile ที่เน้นการร่วมมือกันระหว่าง Dev กับ Customer เพื่อตัดสินใจร่วมกันว่าควรสร้างอะไร


สิ่งสำคัญคือ Dev ต้องเรียนรู้ความรู้ในธุรกิจที่ทำอยู่ มากกว่าแค่การเรียนรู้ภาษาโปรแกรมใหม่ๆ ความเข้าใจนี้จะช่วยให้สามารถเสนอแนวคิดที่มีและสามารถอธิบาย Performace ของ Software ที่สร้างได้ดีมากกว่าเดิม

นอกจากนี้ Fowler ยังเน้นเรื่องความรับผิดชอบต่อผลกระทบของ Software หาก Dev ที่เอาเปรียบผู้ใช้ พวกเขาต้องรับผิดชอบต่อการตัดสินใจนั้น Dev ควรเป็นกระบอกเสียงปกป้อง User และใช้ความสามารถในการแก้ปัญหา เช่น การคุกคามออนไลน์ หรือ Privacy
